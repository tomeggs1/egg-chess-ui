  What to look for. Options 0–3 and 5 keep currentColor, so the four category
  colors survive — compare the gold / steel / verdigris / moss runs down each rail.
  Option 4 does not. Every glyph is the same fixed gold, because the fill comes from the shared
  gradient rather than from color. That is the whole trade: richer metal, but no
  per-category tinting and no muted or disabled states. It is why it suits the six large dialog
  emblems rather than the rail.
  


  Column 6 is option 4 without the cost. Instead of one shared gradient, each icon carries its
  own <linearGradient> inside its own <svg>, with a unique id so nothing
  collides. Because the gradient lives in that svg, currentColor in its stops resolves to
  that icon's color — and color-mix() derives the light and dark ends from it.
  So the ramp follows whatever color you assign, with no per-icon configuration: every existing
  color: ACCENT_* keeps working and simply gains a gradient. Drag grad light and
  grad dark to set how metallic it reads.
  


  Why the light rim, not a dark one. The first cut of this page cast a black shadow under each
  glyph. The CSS was correct and the sliders worked, but the rail is #2c251e — there is
  barely any contrast left below near-black, so the effect was invisible. On dark surfaces depth has to
  be led by a light highlight. Drag rail tint up to lighten the rail and you can watch the
  dark-shadow treatments come back to life — which is the argument for the recessed niche and coin
  plate, since both supply their own lighter surround for a shadow to fall on.
  


  Drag icon down to 16px — the size used inline in the move list and status lines.
  That is where heavy treatments stop reading and start looking like dirt. The rail itself renders at
  20px, and dialog emblems at 40–56px, so whatever you pick has to survive all three.
